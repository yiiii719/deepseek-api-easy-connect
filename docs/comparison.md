# 与官方 App 的对照：哪些一样、哪些只是像、哪些没有

一句话：**交互形状和行为语义基本对齐，底层链路不是同一条**。
官方 App 说的是它自己后端（账号体系 + 免费额度 + 私有接口），本复刻说的是 DeepSeek 公开 API（你的 key）。
这不是"做得不够"，而是两套东西的边界。

## 一、逐项对照

图例：✅ 行为一致 · 🟡 近似/有替代 · ❌ 没有

| 能力 | 官方 App | 本复刻 | 判定 |
|---|---|---|---|

| 深度思考（思考块） | 内置 R1 类模型 | `deepseek-v4-pro` + `effort`，思考块可折叠、显示用时 | ✅ |

## 二、为什么不可能"完全一模一样"

1. **协议不同**：官方 App 打的是 `chat.deepseek.com` 的私有接口（带设备指纹、账号 token、会话同步、埋点）。
   本复刻打的是 `api.deepseek.com`（公开文档化的 OpenAI 兼容接口）。前者的字段、风控、限额都不公开。
2. **免费额度是账号侧的**：官方 App 的"免费"来自平台给的额度，公开 API 没有这个池子；
   要做到"完全一样免费"，只能去逆向它的私有接口——那是账号风险行为，而且随时会变。
3. **原生能力**：推送、系统级分享、相册直读、ASR、部分设备特性需要原生层。
   PWA 能覆盖"用起来像 App"，覆盖不了"系统集成"。

## 三、要往"更像"再走，优先级怎么排

| 顺位 | 做什么 | 成本 | 收益 |
|---|---|---|---|
| 1 | **图片理解**：`deepseek-flash` 支持 `image` 输入，把附件改成 `image_url` content 数组 | 小（~60 行） | 补掉最大的功能缺口 |
| 2 | **语音输入接第三方 ASR**（Whisper 兼容端点），不依赖浏览器 | 中 | 手机端稳定可用 |
| 3 | **多端同步**：给自己加个 `POST /api/sync`，或用 WebDAV/S3 存 SQLite 快照 | 中 | 换机不丢历史 |
| 4 | **分享/快捷方式**：`?q=` 已支持，再加一个 Android 分享目标（需要 APK 壳） | 中 | 系统集成 |
| 5 | **工具调用 / MCP**：让模型能查本地文件、跑命令 | 大 | 从"聊天"变"助手" |
| 6 | 原生 APK 壳（WebView） | 中（本机无 SDK） | 图标/通知/返回键更原生 |

## 四、现在这套的定位

- 想要**一模一样**：只能用官方 App。
- 想要**同样的用法 + 自己的 key + 自己的数据 + 更快的壳**：就是现在这套。
- 想要**比官方更强**：任意模型、任意端点、对外 API、可改任何一行代码——这些官方给不了。
